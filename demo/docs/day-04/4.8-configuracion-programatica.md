# 4.8. Configuración programática sin `persistence.xml`

> **Duración estimada:** 20 min (8 min teoría + 12 min práctica)

---

## 🧠 Teoría rápida (8 min)

Llevamos todo el bloque arrancando JPA sin un solo `persistence.xml`. Hoy explicamos **por qué** y **cómo** funciona eso.

### El planteamiento histórico

JPA, por especificación, espera un fichero `META-INF/persistence.xml` con la definición de la "persistence unit" (nombre, lista de entidades, driver, URL, propiedades de Hibernate...). Algo así:

```xml
<persistence-unit name="pizzeria" transaction-type="RESOURCE_LOCAL">
    <class>com.pizzeria.persistence.ingrediente.IngredienteJpa</class>
    <class>com.pizzeria.persistence.pizza.PizzaJpa</class>
    <!-- ... más clases ... -->
    <properties>
        <property name="jakarta.persistence.jdbc.driver" value="org.h2.Driver"/>
        <property name="jakarta.persistence.jdbc.url"    value="jdbc:h2:mem:pizzeria"/>
        <property name="hibernate.dialect"               value="org.hibernate.dialect.H2Dialect"/>
        <!-- ... -->
    </properties>
</persistence-unit>
```

Hace 15 años esto tenía sentido: el XML estaba de moda, "configuración vs código" era una discusión real, y la idea de poder cambiar configuración sin recompilar parecía un valor.

### Por qué hoy no usamos XML

Tres razones principales:

1. **El XML no se valida en tiempo de compilación.** Te equivocas escribiendo el nombre de una clase y lo descubres en runtime.
2. **Hibernate moderno descubre las entidades por sí mismo.** No necesitas listarlas.
3. **Spring Boot y herramientas similares configuran JPA programáticamente.** Si vas a usar Spring, el `persistence.xml` no aparece nunca. Acostumbrarse a la configuración programática es más fiel al ecosistema actual.

### Cómo se configura sin XML con Hibernate 6.x

Hibernate ofrece dos vías:

**a) Vía API de JPA con `Persistence.createEntityManagerFactory("nombre", propiedades)`** — necesita un `persistence.xml` mínimo (un fichero casi vacío que solo declare el nombre). Lo que hicimos arriba pero con un XML "esqueleto".

**b) Vía API nativa de Hibernate con `BootstrapServiceRegistryBuilder` + `MetadataSources`** — sin un solo XML, pero te ata a la API de Hibernate (no a la de JPA estricta).

Para este curso vamos a usar la **vía (a) con XML mínimo**, porque:

- Es **JPA puro**, no API específica de Hibernate.
- El XML queda como **declaración de unidad**, no como hub de configuración. Las propiedades reales viven en código.
- Esto es lo que más se va a parecer a lo que veas en proyectos reales que aún usan JPA puro.

### El `persistence.xml` mínimo

```xml
<?xml version="1.0" encoding="UTF-8"?>
<persistence xmlns="https://jakarta.ee/xml/ns/persistence"
             xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
             xsi:schemaLocation="https://jakarta.ee/xml/ns/persistence
                                 https://jakarta.ee/xml/ns/persistence/persistence_3_0.xsd"
             version="3.0">

    <persistence-unit name="pizzeria" transaction-type="RESOURCE_LOCAL">
        <exclude-unlisted-classes>false</exclude-unlisted-classes>
    </persistence-unit>

</persistence>
```

Eso es **todo el XML que vamos a tener**. Sin listar clases (Hibernate las descubre solo), sin propiedades (las pasamos en código).

## 🛠️ Práctica guiada (12 min)

### Paso 1 — Crear el `persistence.xml` mínimo

En `src/main/resources/META-INF/persistence.xml`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<persistence xmlns="https://jakarta.ee/xml/ns/persistence"
             xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
             xsi:schemaLocation="https://jakarta.ee/xml/ns/persistence
                                 https://jakarta.ee/xml/ns/persistence/persistence_3_0.xsd"
             version="3.0">

    <persistence-unit name="pizzeria" transaction-type="RESOURCE_LOCAL">
        <exclude-unlisted-classes>false</exclude-unlisted-classes>
    </persistence-unit>

</persistence>
```

> Si ya tenías un XML largo del Bloque 2 con clases y propiedades, **sustitúyelo** por este. Borrar es mejorar.

### Paso 2 — Refactor del `JpaBootstrap`

Tu `JpaBootstrap` ya tenía la idea correcta desde **4.1**. Vamos a desmenuzar las propiedades por sección para que se entienda qué es cada cosa:

```java
package com.pizzeria.infrastructure;

import jakarta.persistence.EntityManager;
import jakarta.persistence.EntityManagerFactory;
import jakarta.persistence.Persistence;

import java.util.HashMap;
import java.util.Map;

public final class JpaBootstrap {

    private static final String PERSISTENCE_UNIT = "pizzeria";
    private static EntityManagerFactory emf;

    private JpaBootstrap() {}

    public static synchronized EntityManagerFactory factory() {
        if (emf == null) {
            emf = Persistence.createEntityManagerFactory(PERSISTENCE_UNIT, buildProperties());
        }
        return emf;
    }

    public static EntityManager openEntityManager() {
        return factory().createEntityManager();
    }

    public static synchronized void shutdown() {
        if (emf != null && emf.isOpen()) {
            emf.close();
            emf = null;
        }
    }

    private static Map<String, Object> buildProperties() {
        Map<String, Object> props = new HashMap<>();

        // --- Conexión JDBC ---
        props.put("jakarta.persistence.jdbc.driver",   "org.h2.Driver");
        props.put("jakarta.persistence.jdbc.url",      "jdbc:h2:mem:pizzeria;DB_CLOSE_DELAY=-1");
        props.put("jakarta.persistence.jdbc.user",     "sa");
        props.put("jakarta.persistence.jdbc.password", "");

        // --- Hibernate ---
        props.put("hibernate.dialect",        "org.hibernate.dialect.H2Dialect");
        props.put("hibernate.hbm2ddl.auto",   "create-drop");
        props.put("hibernate.show_sql",       "true");
        props.put("hibernate.format_sql",     "true");
        props.put("hibernate.highlight_sql",  "true");

        return props;
    }
}
```

Las propiedades por bloque:

- **Conexión JDBC** — qué driver, qué URL, qué credenciales. Aquí va todo lo que cambiaría al pasar de H2 a Postgres o MySQL.
- **Hibernate** — comportamiento del ORM: dialecto, generación de schema (`hbm2ddl.auto`), logs.

### Paso 3 — Variantes útiles para tener a mano

Para que veas que solo es cuestión de cambiar propiedades, aquí van dos variantes habituales que en el curso no usamos pero conviene conocer:

**H2 en fichero (sobrevive entre ejecuciones):**

```java
props.put("jakarta.persistence.jdbc.url", "jdbc:h2:./data/pizzeria");
props.put("hibernate.hbm2ddl.auto", "update");  // no recreamos cada vez
```

**Postgres en local:**

```java
props.put("jakarta.persistence.jdbc.driver",   "org.postgresql.Driver");
props.put("jakarta.persistence.jdbc.url",      "jdbc:postgresql://localhost:5432/pizzeria");
props.put("jakarta.persistence.jdbc.user",     "postgres");
props.put("jakarta.persistence.jdbc.password", "postgres");
props.put("hibernate.dialect",                 "org.hibernate.dialect.PostgreSQLDialect");
```

(Necesitarías añadir la dependencia del driver de Postgres al `pom.xml`.)

### Paso 4 — Validar que sigue funcionando

Ejecuta cualquiera de los demos previos (`IngredienteRepoDemo`, `PizzaRepoDemo`). Debe seguir comportándose igual. La diferencia es:

- Ya no hay `persistence.xml` con propiedades.
- Toda la configuración vive en `JpaBootstrap`, en código, **tipado**, **revisable**, **versionable**.

### Mini-reto

Sin tocar nada más, cambia en `JpaBootstrap`:

```java
props.put("hibernate.show_sql", "false");
```

Vuelve a ejecutar `PizzaRepoDemo` y comprueba que ya no se ven los `SELECT`/`INSERT` en consola. Luego restáuralo a `true`: durante el curso queremos verlos para aprender.

### Checkpoint

- [ ] El `persistence.xml` es de 10 líneas, sin clases ni propiedades.
- [ ] `JpaBootstrap` tiene todas las propiedades de configuración, agrupadas por tipo.
- [ ] Has comprobado que cambiar una propiedad en código cambia el comportamiento de inmediato.

---

## 🎯 Cierre

Mantener un fichero XML solo para declarar el nombre de la unidad es **el mínimo de fricción** con la especificación JPA. Toda la configuración que importa vive donde debe vivir: en código, tipada y versionada.

En **4.9** cerramos el bloque con una mirada al **`persistence.xml` clásico** (el que tenía propiedades y listaba clases): una referencia rápida para que cuando lo encuentres en proyectos antiguos sepas leerlo.

> **Idea para llevarse:** XML mínimo, configuración en código. Si te haría daño compilar para cambiar una URL, parametriza con variables de entorno; eso ya es ingeniería de despliegue, no JPA.
