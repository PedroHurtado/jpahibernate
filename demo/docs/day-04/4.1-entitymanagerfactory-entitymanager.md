# 4.1. `EntityManagerFactory` y `EntityManager`

> **Duración estimada:** 25 min (8 min teoría + 17 min práctica)

---

## 🧠 Teoría rápida (8 min)

Hasta aquí hemos diseñado: dominio, entidades JPA, mappers y los esqueletos de los repositorios. Pero **nada se ha guardado todavía**. Hoy entra en escena la pieza que falta: el `EntityManager`.

### Las dos piezas: factory y manager

JPA define dos abstracciones que conviene no confundir:

**`EntityManagerFactory`** — la fábrica.

- Es **cara de crear**. Por dentro arranca el pool de conexiones, escanea las entidades, valida el mapeo, prepara el dialecto SQL del motor, lee la configuración…
- Es **thread-safe**.
- Se crea **una vez** al arrancar la aplicación y se **cierra al apagar**. En una aplicación de escritorio o consola, normalmente solo hay una.

**`EntityManager`** — el trabajador.

- Es **barato de crear**.
- **No es thread-safe**.
- Representa una **sesión de trabajo** con la base de datos: dentro de él vive el **contexto de persistencia** (la caché de primer nivel) y normalmente coincide con una unidad de trabajo (típicamente una transacción).
- Se crea, se usa y se cierra. Ciclo corto.

> Analogía: la `EntityManagerFactory` es el horno de la pizzería (se enciende al abrir, se apaga al cerrar). El `EntityManager` es cada bandeja que metes y sacas. Compartes el horno, no compartes la bandeja entre cocineros.

### Cómo se crea cada una

`EntityManagerFactory` se crea con `Persistence.createEntityManagerFactory("nombre-persistence-unit")`. Tradicionalmente esa "persistence unit" estaba definida en `persistence.xml`. **Nosotros vamos a configurarla programáticamente** (sin XML); eso lo veremos en detalle en **4.8**. De momento basta con saber que existe esa configuración.

`EntityManager` se crea con `emf.createEntityManager()`.

### El patrón mínimo de uso

```java
EntityManagerFactory emf = Persistence.createEntityManagerFactory("pizzeria", props);

EntityManager em = emf.createEntityManager();
try {
    em.getTransaction().begin();
    // ... trabajo ...
    em.getTransaction().commit();
} catch (RuntimeException e) {
    if (em.getTransaction().isActive()) em.getTransaction().rollback();
    throw e;
} finally {
    em.close();
}

// al cerrar la app:
emf.close();
```

Cinco ideas para retener:

1. **Una `EntityManagerFactory` por aplicación**, no por petición.
2. **Un `EntityManager` por unidad de trabajo**, no compartido.
3. **Siempre cerrar el `EntityManager`** en un `finally`.
4. **Siempre `rollback`** si la transacción sigue activa al saltar excepción.
5. **La `EntityManagerFactory` se cierra al final** de la vida de la aplicación.

## 🛠️ Práctica guiada (17 min)

Vamos a montar el bootstrap mínimo: una clase que construye la `EntityManagerFactory`, un helper para abrir `EntityManager`s, y un `main` que arranca todo y comprueba que la conexión a H2 funciona.

### Paso 1 — Añadir dependencias (si no están)

En el `pom.xml`:

```xml
<dependencies>
    <dependency>
        <groupId>org.hibernate.orm</groupId>
        <artifactId>hibernate-core</artifactId>
        <version>6.4.4.Final</version>
    </dependency>
    <dependency>
        <groupId>com.h2database</groupId>
        <artifactId>h2</artifactId>
        <version>2.2.224</version>
    </dependency>
    <dependency>
        <groupId>jakarta.persistence</groupId>
        <artifactId>jakarta.persistence-api</artifactId>
        <version>3.1.0</version>
    </dependency>
</dependencies>
```

### Paso 2 — Crear el bootstrap

Crea `com.pizzeria.infrastructure.JpaBootstrap`:

```java
package com.pizzeria.infrastructure;

import jakarta.persistence.EntityManager;
import jakarta.persistence.EntityManagerFactory;
import jakarta.persistence.Persistence;

import java.util.HashMap;
import java.util.Map;

public final class JpaBootstrap {

    private static EntityManagerFactory emf;

    private JpaBootstrap() {}

    public static synchronized EntityManagerFactory factory() {
        if (emf == null) {
            emf = Persistence.createEntityManagerFactory("pizzeria", buildProperties());
        }
        return emf;
    }

    public static EntityManager openEntityManager() {
        return factory().createEntityManager();
    }

    public static synchronized void shutdown() {
        if (emf != null && emf.isOpen()) {
            emf.close();
            emf = null;
        }
    }

    private static Map<String, Object> buildProperties() {
        Map<String, Object> props = new HashMap<>();
        props.put("jakarta.persistence.jdbc.driver", "org.h2.Driver");
        props.put("jakarta.persistence.jdbc.url", "jdbc:h2:mem:pizzeria;DB_CLOSE_DELAY=-1");
        props.put("jakarta.persistence.jdbc.user", "sa");
        props.put("jakarta.persistence.jdbc.password", "");
        props.put("hibernate.dialect", "org.hibernate.dialect.H2Dialect");
        props.put("hibernate.hbm2ddl.auto", "create-drop");
        props.put("hibernate.show_sql", "true");
        props.put("hibernate.format_sql", "true");
        return props;
    }
}
```

> No te preocupes ahora por el detalle de las `properties` ni por la ausencia de `persistence.xml`. Eso lo desmenuzamos en **4.8** y **4.9**. Hoy solo necesitas que arranque.

### Paso 3 — Un `main` que arranque y cierre

Crea `com.pizzeria.Main`:

```java
package com.pizzeria;

import com.pizzeria.infrastructure.JpaBootstrap;
import jakarta.persistence.EntityManager;

public class Main {

    public static void main(String[] args) {
        EntityManager em = JpaBootstrap.openEntityManager();
        try {
            System.out.println("EntityManager abierto: " + em);
            System.out.println("¿Está abierto? " + em.isOpen());
        } finally {
            em.close();
            JpaBootstrap.shutdown();
        }
    }
}
```

### Paso 4 — Ejecutar y observar

Al ejecutar `Main` deberías ver en consola:

- Una serie de logs de Hibernate inicializándose.
- Los `CREATE TABLE` correspondientes a las entidades del Bloque 3 (ahí vas a comprobar que el mapeo del Bloque 3 era correcto).
- El mensaje `EntityManager abierto: ...`.

> **Si no ves los `CREATE TABLE`**, probablemente Hibernate no ha encontrado tus `@Entity`. Asegúrate de que están en el classpath y que las propiedades del bootstrap incluyen `hibernate.hbm2ddl.auto`.

### Checkpoint

- [ ] La aplicación arranca sin excepciones.
- [ ] Ves los `CREATE TABLE` de `PizzaJpa`, `IngredienteJpa`, `PizzaIngredienteJpa`, `UserJpa`, `CommentJpa`.
- [ ] El programa termina limpiamente (sin warnings sobre conexiones abiertas).

## 🎯 Cierre

Tenemos el `EntityManager` listo pero todavía no hemos guardado nada. En **4.2** vamos a ver los **estados** por los que pasa una entidad y por qué entenderlos es lo que separa al que "usa JPA" del que "entiende JPA".

> **Idea para llevarse:** una `EntityManagerFactory`, muchos `EntityManager`. La factory es cara y compartida; el manager es barato y desechable.
